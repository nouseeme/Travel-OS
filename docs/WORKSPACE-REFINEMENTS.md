## Behavior

- Kanban cards have tighter spacing, shorter previews, and a button spanning the card surface. Drag handles, stage/status selectors and edit controls remain independent. Keyboard users can open the entire card button.
- Multiple active administrators are supported through People → Atur akses → Role. Admin capabilities are managing people, seeing team tasks in Home, confirming/rejecting corrections and voiding transactions. Module privileges still determine reading/editing modules; configuration, export and audit follow module access. The last active admin remains protected. Viewing another person's internal task does not grant editing it.
- Trips use Planned → Confirmed → In Progress. Confirmed moves automatically when its start date is at most two days away, using the workspace's timezone, including on subsequent overdue dates. Planned remains unconfirmed. The migration installs a one-minute Supabase Cron job where pg_cron is available; snapshots also reconcile the rule and open Home/Trips refresh every minute. Completed/Cancelled are terminal outcomes in the table archive; unfinished tasks are cancelled when a trip is closed, while completed tasks and cash history remain stored.
- Finance uses one Record transaction form for both directions. Amount receives initial focus, groups digits while typing, accepts up to two decimal places, and uses exact integer hundredths in client calculations and PostgreSQL numeric storage. Quotations and budgets use the same input/arithmetic. Transactions have a required title and optional note. Legacy descriptions are preserved and copied into titles. Amount signs and colors express receipt/payment; summary figures remain cash flow, including capital/loans, and are not accounting profit.
- Finance edit privilege allows proposing a correction with a reason. The proposal stores the original record and version, leaves posted values/totals unchanged, and waits for an admin with Finance access to confirm or reject it. A second pending proposal is rejected. Approval checks the transaction version, category and date again, applies the change atomically and records the reviewer. Void is admin-only and closes pending corrections. CSV includes titles, decimal amounts and current category names.
- Internal Docs has a searchable, paginated Judul/Date/Creator/Category table. Documents use the existing Markdown-backed WYSIWYG editor and document templates, preserve creators, protect unsaved edits and reject stale saves. View privilege cannot edit or publish. Existing admins receive Docs edit; existing members and future invitations default to no Docs access until assigned.
- A Docs editor can preview and explicitly publish the entire note through a View/read-only snapshot link, with expiry and revoke. Later private edits do not update public content until Publish update. Tokens are hashed; anonymous access is limited to the snapshot, with sanitized Markdown, no client scripts, no remote images, and no internal navigation or edit endpoint.
